① 先搞懂：这是什么

这是一个跑在你 VPS 上的运维配置网页。以前要改「哪个学期是权威学期」「AI 用什么模型」「学号导入分析到第几学期」这些，得 SSH 上去手改文件、重启服务、有时还要本地重新 build 再 push。现在这些都变成网页上的表单和按钮。

一句话理解它的位置：它是一个「遥控器」。它自己不存数据，只是帮你去改三个地方的配置 —— 仓库文件、VPS 上的 .env 文件、Cloudflare 的项目变量 —— 然后触发相应的生效动作（重新构建 / 重启服务 / 重新部署）。

怎么打开面板

面板只绑定在 VPS 的 127.0.0.1:8790，公网访问不到（这是刻意的安全设计）。要访问得先用 SSH 隧道把它「借」到你自己电脑的同一个端口：

  1. 在本地终端建立隧道（保持这个窗口开着）：
    ssh -L 8790:127.0.0.1:8790 <VPS别名>
    <VPS别名> = 你本地 ~/.ssh/config 里配好的主机别名（含跳板机和密钥）。
  2. 浏览器打开 http://127.0.0.1:8790
  3. 用密码登录 —— 密码是 VPS 上 ~/apps/jxnu-admin/admin.env 里的 ADMIN_PASSWORD（首次安装时脚本随机生成并打印过一次）。

登录后 8 小时有效；服务重启会让所有人重新登录。顶部导航栏有 7 个页面 + 右上角「退出」。

三类改动的区别（最重要，先记住这个）

面板上每一处配置，按「改完怎么生效、多久生效」分成三类。看懂这张表，就不会懵了：

标记改的是什么怎么生效多久
仓库类 仓库里的文件（当前学期、构建配置） 面板自动跑一整套流水线：停同步定时器 → 拉取最新 → 改文件 → 重新 build → 推送 → 网站自动重新部署 数分钟，中途别重复点
VPS 本机 VPS 上的 .env 文件（学期指向、账号密码、阈值） 改完就写进文件；有的即时生效，有的要点一下「重启服务」 秒级
Cloudflare 网站后端的环境变量（AI 配置、密钥） 先「PATCH 到 Cloudflare」保存，再点「触发新部署」才真正生效 保存秒级，部署要几分钟
只读 状态、日志 只是看，不改任何东西 —

⚠ 「仓库类」和「Cloudflare 类」都是几分钟才生效，不是点完立刻见效。点完按钮页面会逐步显示每一步的执行输出（拉取、构建、推送……），看到最后一步 OK 就成了，然后等 CF Pages 部署完（约 1–3 分钟）网站才更新。别因为「网站没马上变」就反复点。

② 逐页说明

总览 只读

进门第一页，纯看状态、不改东西。三块：

  • 服务状态：四个服务是 active（绿）还是别的（红），以及每小时同步定时器的下次触发时间。
  • 仓库最新提交：VPS 上仓库当前停在哪个 commit。
  • 学期旋钮汇总：把散落在各处的「学期」相关值列在一起。

💡 页面顶部如果出现黄色「学期旋钮不一致」警告条，说明 isCurrent / SYNC_SEM / KKAP_SEMESTER / liveEnrollmentSemester 这四个本该相等的值对不上了 —— 通常是换学期时漏改了某一处。照着换学期流程补齐即可。

学期管理 仓库类 VPS 本机

面板最核心的一页，管「到底哪个学期是权威」。分四块：

区块作用类型
当前学期（meta.json isCurrent） 决定「预选」页展示哪个学期的课程目录。单选一个学期 → 点「设为当前学期并重建推送」。 仓库类
构建配置（build_config.json） 四个旋钮打包保存，详见下方。点「保存并重建推送」。 仓库类
每小时同步目标学期（SYNC_SEM） 每小时抓开课/容量数据时，落到哪个学期目录。改完下次同步自动生效。 VPS 本机
实时人数学期（KKAP_SEMESTER） 实时已选人数快照声明的学期。改完要重启 kkap-realtime。 VPS 本机

构建配置里的四个旋钮：

  • testSemesters —— 填进去的学期会在「正选/补退选」侧显示「（测试）」后缀和提示横幅（告诉用户这是借来的测试数据）。空格或逗号分隔多个。
  • mirrorSemesters —— 把已有学期的数据克隆成另一个学期标签用于测试。JSON 格式 {镜像来源学期: [克隆出的目标学期...]}，例如 {"2026-09":["2025-09"]} = 把 2026-09 的数据复制一份贴上 2025-09 的标签。真实数据到位后清空成 {}。
  • liveEnrollmentSemester —— 前端在哪个学期开启 30 秒实时人数轮询。留空 = 关闭实时人数轮询（注意：这里的「留空」是关闭，不是「不修改」）。
  • featureFlags —— studentImport（学号导入入口）和 aiPick（AI帮我选 tab）的总开关，true/false 下拉。这是给用户看的功能开关。

⚠ 「当前学期」和「构建配置」都是仓库类，点保存后会跑几分钟的 build+push 流水线，页面会逐步显示进度。中途不要重复提交、不要关页面。

学号导入 VPS 本机

只管一个东西：LIVE_PLANNING_TERM_OVERRIDE —— 学号一键导入时，把学生的学分分析算到「第几学期」为止。

  • 默认留空：系统自动从教务当前学期推导规划学期、在读学期、学分统计截止点 —— 平时不用管。
  • 寒暑假窗口期教务的默认学期可能滞后/超前，导致导入算错学期，这时手工填一个覆盖值。
  • 格式是教务的学年学期写法，例如 26-27第1学期。
  • 想恢复自动：输入框留空 + 勾选「清除该键」复选框再保存（单纯留空 = 不修改，勾了清除才是真删除）。
  • 改完点保存后，结果页有「重启 jxnu-live」按钮，重启后才生效。

AI · Cloudflare Cloudflare

管「AI帮我选」后端 —— 用哪家 API、什么模型、每日用多少额度。这一页操作的是 Cloudflare Pages 的环境变量，所以需要先给面板一把 Cloudflare 的钥匙。

首次要先配钥匙：在 VPS 的 ~/apps/jxnu-admin/admin.env 里填 CF_ACCOUNT_ID 和 CF_API_TOKEN，然后重启 jxnu-admin。Token 创建方法：Cloudflare 控制台 → 右上头像 → My Profile → API Tokens → Create Custom Token，权限选 Account / Cloudflare Pages / Edit。没配之前，这一页会显示配置指引而不是表单。

配好后这一页能：

  • 看当前生产环境的所有变量（secret 类只显示「已设置」，看不到明文 —— 这是对的）。
  • 改这些明文变量：AI_BASE_URL（API 地址）、AI_MODEL（模型名）、AI_VOTER_DAILY/AI_SITE_DAILY_CALLS/AI_SITE_DAILY_TOKENS（限额）。
  • 改这些密钥（secret）：AI_API_KEY、LIVE_SECRET。

🚨 两步才生效：先点「PATCH 到 Cloudflare」保存变量，再点「触发新部署」 —— 不重新部署的话，改的变量不会被网站用上。

🚨 LIVE_SECRET 必须两边一起改：这一页改的是 Cloudflare 侧；VPS 侧的同名值在「凭据」页的 live.env。两边不一致，学号实时导入会退回读旧的 D1 快照。

服务 VPS 本机

  • 常驻服务重启：kkap-realtime（实时人数）、jxnu-live（学号导入上游）、jxnu-admin（面板自己 —— 重启它会先返回页面再延迟 1 秒执行，你会短暂掉线再刷新即可）。
  • 立即跑一次同步：手动触发每小时那套数据同步（异步，进度去「日志」页看）。
  • 探测容量阶段：跑一次 crawl_capacity --probe 3，帮你确认当前选课阶段该用哪个 XK_STEP 前缀（≤180 秒，同步返回结果）。
  • kkap.env 配置：实时人数学期、刷新秒数（≥10）、CORS 白名单。改完重启 kkap-realtime。

凭据 VPS 本机

管两个 .env 文件里的账号密码和参数。所有值回显都打码（只露末几位），输入框留空 = 不修改这一项。

  • sync.env（每小时同步 / 容量爬取用）：教务账号 XK_USERNAME/XK_PASSWORD、阶段前缀 XK_STEP、三个安全阈值。保存即生效，无需重启（每次同步现读）。
  • live.env（实时课表服务用）：教务账号、LIVE_SECRET、缓存时长。改完重启 jxnu-live。

⚠ 教务账号在 sync.env 和 live.env 里各存一份，换密码时两处都要改。
⚠ XK_STEP：预选阶段用 Step1，正选/补退选阶段用 Step3（拿不准先用「服务」页的「探测容量阶段」核对）。

日志 只读

选一个服务 + 行数（≤500），看它的 journalctl 日志。同步出问题、服务起不来，都来这里看原因。

③ 照着做：常见场景

场景 A：新学期开始了（换季）

这是最容易漏的复合操作 —— 四个「学期」旋钮必须一起换成新学期，否则总览页会报「不一致」。前提是新学期的数据目录已经存在（每小时同步会去抓，或你已手动放好 raw 数据）。

  1. 学期管理 → 当前学期：选中新学期 → 「设为当前学期并重建推送」仓库类（等它跑完几分钟）
  2. 学期管理 → 构建配置：liveEnrollmentSemester 改成新学期 → 「保存并重建推送」仓库类
  3. 学期管理 → 每小时同步目标学期：SYNC_SEM 改成新学期 → 保存 VPS 本机
  4. 学期管理 → 实时人数学期：KKAP_SEMESTER 改成新学期 → 保存，然后在结果页点「重启 kkap-realtime」VPS 本机
  5. 回总览确认黄色「不一致」警告条消失。

如果新学期还带测试数据（借用别的学期的开课数据），额外在构建配置里配 testSemesters / mirrorSemesters；真实数据到位后再清空它们。

场景 B：选课阶段切换了（预选 → 正选）

  1. 服务 → 「探测容量阶段」，看输出确认现在该用哪个 XK_STEP。
  2. 凭据 → sync.env → 把 XK_STEP 改成正确前缀（正选一般是 Step3）→ 保存 VPS 本机（即时生效）。
  3. 可选：服务 → 「立即跑一次同步」，然后去日志页确认容量抓取正常（不再是全 0）。

场景 C：换 AI 模型 / 换供应商

  1. AI · Cloudflare → 修改环境变量：改 AI_BASE_URL（新供应商的 API 地址）和 AI_MODEL（新模型名）；换供应商通常还要填新的 AI_API_KEY。
  2. 点「PATCH 到 Cloudflare」保存。
  3. 点「触发新部署」Cloudflare —— 等 1–3 分钟部署完才生效。

只要新供应商是 OpenAI 兼容接口（/v1/chat/completions）就能直接换，不用改代码。

场景 D：学号导入把学期算错了

  1. 学号导入 → LIVE_PLANNING_TERM_OVERRIDE 填正确的学年学期（如 26-27第1学期）→ 保存。
  2. 结果页点「重启 jxnu-live」VPS 本机。
  3. 恢复自动推导时：输入框留空 + 勾「清除该键」再保存。

场景 E：某个服务好像挂了

  1. 总览看哪个服务不是绿色 active。
  2. 日志页选那个服务，看最近日志找原因。
  3. 服务页点对应「重启」。

④ 出问题怎么办

现象原因 / 处理
浏览器打不开面板SSH 隧道断了。重新执行 ssh -L 8790:127.0.0.1:8790 <VPS别名> 并保持窗口。
「保存构建配置」跑完了，但网站没变化①正常的话要等 CF Pages 部署 1–3 分钟；②如果结果页某一步是「失败」红标，看那一步的输出。注意：仓库侧支持 build_config 的代码要已经 push 到 main，VPS 才会用上它 —— 若这批改动还没提交上线，面板保存了也不生效。
AI 页显示「未配置凭据 / requests 不可用」前者：admin.env 填 CF_ACCOUNT_ID+CF_API_TOKEN 后重启面板。后者：VPS 装 python3-requests，或直接去 Cloudflare 控制台手改。
保存 env 时报「非法字符」密码含空格或 ' " \ $ ` # 这类字符会破坏 shell 解析，被拦下。这种复杂密码请 SSH 上去手改对应 .env 文件。
提示「已有操作进行中」（409）另一个「仓库类」操作正在跑（build+push 需要几分钟）。等它完成再操作。
总览报「学期旋钮不一致」换学期时漏改了某处。照场景 A把四处补齐。

⑤ 通用规矩（记住这几条就稳了）

留空 = 不修改 绝大多数输入框：留空就是「这一项不动」，不会清空原值。

两个例外 liveEnrollmentSemester 留空 = 关闭实时人数；LIVE_PLANNING_TERM_OVERRIDE 要勾「清除」才是删除。

敏感值只打码 密码/密钥回显永远是打码的，看不到明文属正常。

仓库类要等 蓝标操作跑 build+push，几分钟，别重复点、别关页面。

改密钥同步两边 LIVE_SECRET 改了 Cloudflare 侧也要改 VPS 侧（反之亦然）。

先探测再改阶段 拿不准选课阶段时，先「探测容量阶段」再改 XK_STEP。
